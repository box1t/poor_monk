### Allocators and mem management

У всех станд. конт есть последний шаблонный параметр аллокатор.

Вызов new - долгая операция.
Может быть даже дольше чем спуск по дереву.
new вызывается каждый раз при вставке элементов в set, list, map.
Ассимптотическая сложность вставки для этих контейнеров не учитывает выделение ресурса через new.
И это может быть даже дольше вставки!

Но это не единственная проблема.

Зачем вообще нужна динамическая память?
Почему бы не завести список, использующий стековую память, а не динамическую?
Но... в таком формате только new. Хотя это не всегда уместно.
Именно для этого и существует аллокатор!
Аллокатор - промежуточное звено между контейнером и вызовом оператора new.
Это прослойка.
Контейнер обращается не к new, а к чему-то другому.
Аллокатор кастомизирует поведение контейнера при выделении памяти.

Container -> Allocator -> operator New -> malloc -> OS

***
Самый тупой аллокатор - стд версия.
Что он делает в базовом сценарии?

Есть 4 основных метода:
- allocate (заменяет обращение к оператору new, просто выделяя память)
- deallocate

```c++
template <typename T>
struct allocator {
	T* allocate(size_t count) // Возвращает указатель на тип Т, принимает число
	{
		return reinterpret_cast<T*>(new char[count*sizeof(T)]);	
	}
	void deallocate(T* ptr, size_t ) // count should be the same
	{
			delete[] reinterpret_cast<char*>(ptr);
	}
	template <typename U, typename... Args> // codegeneration
	void construct(U* ptr, const Args&... args) {
		new (ptr) U(args...);
	}
	void destroy(T* ptr) {
		ptr->~T();
	}

};

// У аллокатора нет ни одного поля.

```


Важно различать аллокацию и конструирование.
(аллокатор отдается параметром в конструктор)
аллокатор это четвертое поле у каждого контейнера из стл.

***
POOL allocator.
Изначально выделяет большой массив, а потом из него выдает кусочки.
Он сам поддерживает memory-management, один раз выделяя память.


Stack allocator - не обращается к new.
Все выделяет на стеке.
В конструктор аллокатора будем принимать массив! std::array.

***
Первая проблема: когда у нас лист!!
Лист аллоцирует не инты, а НОДЫ.
И тут...
Когда имеем дело с аллокатором в контейнере, может возникнуть потребность аллоцировать не тот тип, от которого был аллокатор.

Может быть не тип Т, а тип U.

```c++
int main() {
	std::array<char, 1000000> arr;
	StackAllocator<int> alloc(arr);
	std::list<int, StackAllocator<int>> lst; // list from allocator on stack
}
```
