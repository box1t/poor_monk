

emplace_back принимает не объект Т, а АРГУМЕНТЫ, из которых создает Т на месте.

она шаблонная.

```c++
template <typename... Args>
void emplace_back(const Args&... args) {
	new(ptr) T(args...); // объект создается ОДИН раз
}
```

Это не решает проблему глобально.
Если у нас вектор векторов строк, проблема не исчезнет!

проблема не только с пуш бэк.


Любое сохранение данных имеет подобную проблему:
У нас создается промежуточный объект. И решения нет!
как бы мы ни принимали аргументы.

Мув семантика тоже создает промежуточную строку.
Но в списке инициализации конструктора будет забираться ВЛАДЕНИЕ.
Данные забираются, а у донора остаются пустыми.

(речь не о функции std::move)

lvalue, rvalue - свойства ВЫРАЖЕНИЙ, а не типов.

std move перенаправляет поток (чего?), поэтому не происходит лишнего копирования в emplace back (vs push_back)

std move это КАСТ МЕЖДУ ВИДАМИ ВАЛЬЮ.

- rvalue можно передать по const type& и по type&&
- lvalue по const type& и по std::move
