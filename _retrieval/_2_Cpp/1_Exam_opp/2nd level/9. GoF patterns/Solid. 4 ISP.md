24. SOLID: Принцип разделения интерфейсов.

Interface Segregation Principle (ISP) утверждает, что клиенты не должны зависеть от интерфейсов, которые они не используют. 

Предлагается разделять большие интерфейсы на более маленькие и специфичные, чтобы клиенты могли реализовывать только те методы, которые им нужны, а не зависеть от неиспользуемых методов.

Предположим, у нас есть интерфейс `Worker`, который представляет сотрудника и имеет методы для работы и управления задачами:


```cpp
class Worker {
public:
    virtual void work() = 0;
    virtual void manageTasks() = 0;
};
```

Теперь предположим, что у нас есть класс `Developer`, который реализует интерфейс `Worker` и добавляет свой собственный метод `code()` для написания кода:


```cpp
class Developer : public Worker {
public:
    void work() override {
        code();
    }

    void manageTasks() override {}
    void code() {}
};
```

В данном случае, если клиенту (например, классу, который использует объекты типа `Worker`) не нужно управление задачами, но ему нужно только написание кода, ему все равно придется реализовать метод `manageTasks()`, так как он является частью интерфейса `Worker`. Это нарушает принцип разделения интерфейсов.

Для исправления этого нарушения мы можем разделить интерфейс `Worker` на более маленькие интерфейсы:

```cpp
class Workable {
public:
    virtual void work() = 0;
};

class TaskManager {
public:
    virtual void manageTasks() = 0;
};

class Developer : public Workable {
public:
    void work() override {
        code();
    }

    void code() {}
};
```

Теперь клиенты могут реализовывать только необходимые им интерфейсы, что делает код более гибким и избавляет от зависимости от неиспользуемых методов.
