
# Сравнение очереди с деком

В ***деке*** (**Double Ended Queue**) чтение и доступ возможны с обоих концов.

Обычная очередь - частный случай двухконцовой очереди. мы запрещаем в начале дека выход и в конце вход - получаем очередь.
В универсальных ЯП тип данных очередь не встроен по умолчанию.

# Примеры из жизни

Обычная очередь неточно описывает задачу с вагонами: 
- Если мы хотим отцепить последний вагон, увозим поезд. 
- Если отцепить первый вагон - надо отцепить локомотив и отвезти. но отцепить и прицепить - это дек. 

Получается, алгебру поездов можно реализовать деком.

Очередь - это фактически задача поставщик - потребитель. Есть тот, кто направляет, и кто потребляет. Очередь возникает, когда есть разница в скорости притока потребителей и обслуживания.
Пробка, затор - очередь из машин. 

Недостатки нашей очереди - неприменима к зоопарку. Крокодилы не могут пятиться назад, они ползут только вперед. 

Очередь - это труба. обогнать нельзя, пятиться нельзя..

Очередь неуниверсальна.
Задача на очередях выигрывает только при работе с началом и с концом.

# Функциональная спецификация

Очередь - структура с одной читающей головкой и одной записывающей головкой.
Чтение и запись за постоянное время O(1), запись неразрушающая.

Итак, очередь - упорядоченный, одномерный, динамически изменяемый набор компонент, пополнение которого производится на одном конце набора, а всякий доступ к компонентам и удаление обработанных - на другом конце.

*Правила*:
1. Очередь всегда создаётся пустой.
2. Если добавляется компонента к очереди, то результат непустой. 
3. Внесенный в пустую очередь элемент становится первым .
4. Порядок внесения и извлечения элементов всегда сохранён: первым вошёл, первым вышел.

Очередь это очередь, если удовлетворяет правилам очередей.
А функциональная спецификация - руководство для тестов очередей.


*Операции*:
- Создать
- Пусто
- В очередь
- Из очереди
- Первый
- Длина
- Уничтожить

Функция пусто предшествует другим. И если длина пустой очереди 0, это не ошибка. 
Проверка пустоты очереди осуществима за постоянное время.
Чтение из очереди - это удаление элемента.

Посмотреть в очереди можно только на первый элемент. На последний не посмотреть. 
Для просмотра очереди нужна вторая очередь (или файл), чтобы не терять элементы.

Количество компонент - это её длина. Длина очереди - переменная характеристика.
Цена определения длины очереди линейная.
А пространственная сложность тоже линейная - мы вынимаем элемент постепенно.

> хотите тестировать очередь - создайте эти тесты. вот вам готовый десяток тестов для очереди. это и есть функциональная спецификация. 

> тесты пишутся перед программой. они на более высоком уровне, чем программа. они на уровне идеи, алгоритма! тесты не пишем после программного кода


# Логическое описание и физическое представление.

Для работы с очередями надо реализовать операции с их свойствами в ручную, т.к. в универсальных ЯП тип данных очередь не встроен по умолчанию. 

Для этого нужно отобразить структуру очереди на имеющиеся линейные структуры:
файл или массив, - либо создать цепочку компонент на динамических структурах.


```c
typedef struct {
	struct Item* first;
	struct Item* last;
	int size;
} queue;

void Create(queue* q); // 1
bool Empty(const queue* q); // 2
int Size(const queue* q); // 3
bool Push(queue* q, const T t); // 4
bool Pop(queue* q); // 5 
T Top(const queue* q); // 6
void Destroy(queue* q); // 7
void Reverse(queue* q); // 8

```


- Размер очереди хранится в явном виде, функция Size() лишь возвращает его. 
- Функция постановки в очереди Push() выдаёт запрос на выделение памяти языковой среде или напрямую ядру ОС. Если память не выделена, указателю присваивается нулевое значение (в Си) или nil в Паскале, и функция возвращает **false**.
- Функция Pop(), копируя указатель на первый элемент очереди, готовит этот элемент к отсоединению от очереди, ставя ссылку на следующий элемент с последующим уничтожением отсоединенной компоненты по копии ссылки. При этом декрементируется счётчик элементов очереди.
- Top - неразрушающее чтение. Функция Top() определена только на непустых очередях.
- Для уничтожения очереди поочерёдно удаляем все её элементы, сохраняя в локальной перемеенной pi (на мгновение!) перед удалением каждого элемента содержащуюся в нём ссылку на следующий элемент.

Существуют итеративная и рекурсивная процедуры Destroy.

Рекурсивная совмещает *обход* очереди и посещение всех её элементов с одновременным удалением пройденных компонент.



***

```c
typedef struct {
	struct Item* first;
	struct Item* last;
	int size;
} queue;

void Create(queue* q) {
	q->first = q->last = malloc(sizeof(struct Item));
	q->size = 0;
}

bool Empty(const queue* q) {
	return q->size == q->last;
}

int Size(const queue* q) {
	return q->size;
}

bool Push(queue* q, const T t) {
	if(!q->last->next == malloc(sizeof(struct Item))) {
		return false;
	}
	q->last->data = t;
	q->last = q->last->next;
	q->size++
	return true;
}

bool Pop(queue* q) {
	if(q->first == q->last) {
		return false;
	}
	struct Item* pi = q->first;
	q->first = q->first->next;
	q->size--;
	return true;
}

T Top(const queue* q) {
	if(q->size) {
		return q->first->data;
	}
}

// итеративное удаление
void Destroy(queue* q) {
	while(!Empty(q)) {
		struct Item* pi = q->first;
		q->first = q->first->next;
		free(pi);
	}
	free(q->first);
	q->first = q->last = 0;
	q->size = 0;
}

// рекурсивное удаление очереди
void Destroy(queue* q) {
	q->last->next = 0;
	struct Item* pi = q->first;
	q->first = q->first->next;
	free(pi);
	if(q->first) {
		Destroy(q);
	}
	q->last = 0;
	q->size = 0;
}

void Reverse(queue* q)
{
	if(!Empty(q)) // проверка пустой очереди, пустую не реверсируем
	{
		T t = Top(q); // использован почти весь джентельменский набор функций
		Pop(q);
		Reverse(q);
		Push(q, t);
	}
}


```
