
==время работы, сравнение структур, задача в информатике===
Файл - динамический объект, состоящий из последовательных компонент одного типа.
Он появляется пустым.
Заполняя файл, мы его наращиваем, т.к. запись идет в конец. 
Файл имеет имя для обнаружения его на внешнем устройстве памяти.

По отношению к программе есть внешние и внутренние файлы.
Внешние файлы служат для долговременного хранения, указываются в заголовке программы.
Внутренние описаны в типе var (на Паскале).

Файл можно открыть в текстовом и двоичном режимах.
Время жизни файла превышает время жизни программы.

# Функциональная спецификация

```yaml
Это математическое вернеуровневое описание в терминах ЯП.

Для функциональной спецификации:
указываем множество значений, изображений, атрибутов типа, правила интерпретаций.

Множество атрибутов:
- множество операций над значениями типа и их свойство
- множество отношений и их свойства
- выделенные функции

```
***

***Значения*** файлового типа сколь угодно длинные, но конечные последовательности типа Т.
***Множество значений*** определяется конкатенацией двух файлов из компонент одного типа.

***Правила интерпретации***:
1. Определение файла *рекурсивно*: пустой файл является файлом (пока файл не пуст, мы работаем с его компонентами).
2. Если f - файл, t - объект, то конкатенация файла f и объекта t есть файл.
3. Никакие другие значения не являются файлом.
Это определение позволяет построить любой файл.

***Множество атрибутов***:
1. Операция конкатенации несимметрична
2. Операция присваивания - покомпонентное копирование файла в другой с сохранением порядка
3. Отношение равенства: файлы и компоненты одного типа равны при одинаковой длине, равных значениях. Отношение равенства симметрично
4. Функции: создание, доступ, модификация, уничтожение

# Логическое описание и физическое представление

***

В Си для описания файла объявим переменную типа File*
Фактически определяем переменную-дескриптор файла, которая является ссылкой на файл, т.к. в Си нет файлового типа.

Сравнение двух файлов - это цикл с предусловием равенства буферов.
Перезапись файла легче делать с конца, поэтому мы занимаемся копированием компонент.

Абстракция *файла* - это *последовательность*.
Файл доступен за линейное время, поэтому выгодно работать с текущей компонентой, чтобы не ездить к соседним за линейное время.

А у *файла прямого доступа* абстракция *массив*, и его нельзя называть файлом.
Файлы прямого доступа Вирт не включил в Паскаль из-за проблем с физической реализации памяти во времена бабушек и дедушек - барабаны! Паскаль даёт идеальный, неудачный пример файлов, там мы работаем почти с кинолентами фильмов.
