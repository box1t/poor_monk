

Деревья поиска и упорядоченные таблицы дают логарифмическое время доступа.

Обращение к элементу данных в таблице *по фактическому адресу* ***при его вычислении по ключу*** даст нам доступ за постоянное время.

Для этого таблицу поместим в массив (поскольку в нём доступ за постоянное время), построим преобразование ключей в индексы, и массивы индексируем с 0.

Применим подход для доступа с произвольным ключом. 
Преобразование ключей в лоб по схеме Горнера крайне невыгодно по памяти.

Тогда используем методом прямой адресации таблиц на основании ключа - хеширование. Он вычислит адрес за постоянное время проверкой точного совпадения ключей. 
 
При поиск в таблице в случае неудачи по вычисленному адресу уже находися элемент с другим ключом, поэтому проверяем точное совпадение ключей.
Такие ситуации называются коллизиями (конфликтами).

# Выбор хеш-функции.

Хорошая хеш-функция равномерно распределит ключи по всему диапазону значений индекса. При этом она вычисляется за небольшое число операций.

Примеры хеш-функций: 
- умножение ключа на константу
- размер таблицы вычисляется как степень двойки, из двоичного представления ключа вырезается середина.

# Рехеширование
Если строка, соответствующая ключу, не содержит искомого элемента с этим же ключом, проведём переадресацию ключа внутри таблицы.
Она должна быть такой же быстрой, как и первичное хеширование.

Методы:
1. Организуем *список строк* с идентичным первичным ключом. 
1.1. *Недостаток* - линейное время поиска, концентрация строк вокруг первичных ключей вместо их равномерного рассеивания по массиву.
1.2. Квадратичное рехеширование. Требует сортировки, но при упорядочивании элементов теряем возможность быстрого доступа по адресу при помощи хеш-функции.
2. ***Открытая адресация***. Ищем желаемый элемент в окрестности этого ключа.
3. ***Случайное рехеширование***. Высоко производительный метод.
