### `assert` в C

#### 📌 **Что это и для чего?**

- `assert` 
	- это макрос в C, используемый для отладки программ. 
	- Он проверяет, выполняется ли условие, и если нет, программа аварийно завершает выполнение, выводя сообщение об ошибке. Это помогает выявлять ошибки во время разработки.
	- Гарантирует корректность входных данных.
	- Валидирует инварианты в сложных СД.



---

### 📌 **Методы и сигнатуры**

`assert` объявляется в заголовочном файле `<assert.h>`:

```c
#include <assert.h>
void assert(int expression);
```

✅ Если `expression` равно `0` (ложно), программа завершится с ошибкой.  
✅ Если `expression` не `0` (истина), ничего не происходит.

Пример:

```c
#include <assert.h>
#include <stdio.h>

void test(int x) {
    assert(x > 0);  // Завершит программу, если x <= 0
    printf("x is valid: %d\n", x);
}

int main() {
    test(5);  // OK
    test(-1); // Ошибка: программа завершится с сообщением
}
```

---

### 📌 **Связанные термины**

- **Предусловия (Preconditions)** — гарантии перед вызовом функции.
- **Постусловия (Postconditions)** — гарантии после выполнения функции.
- **Инварианты (Invariants)** — условия, которые должны быть истинными на всём протяжении работы программы.
- **Отладочные проверки (Debug Assertions)** — проверки, которые работают только в отладочной версии программы.
- **Макрос NDEBUG** — если определён, `assert` отключается (подробнее ниже).

---

### 📌 **Какой подход отражает?**

- `assert` относится к **защитному программированию** (_Defensive Programming_).
- Входит в концепцию **контрактного программирования** (_Design by Contract_), где выполняются проверки входных и выходных данных.
- Альтернатива явным `if`-проверкам с `exit()` или `abort()`.

---

### 📌 **Глубокие технические особенности**

1. **Как `assert` работает внутри?**
    
    - При ложном `expression`, макрос вызывает `abort()`, завершая программу.
    - Выводит сообщение в `stderr` с названием файла, строки и вызовом `expression`.
2. **Как отключить `assert` в релизной сборке?**
    
    - Определение `NDEBUG` отключает `assert` на этапе компиляции.
    - Если `#define NDEBUG` перед `#include <assert.h>`, `assert(x)` просто не будет компилироваться.

```c
#define NDEBUG
#include <assert.h>

int main() {
    assert(0); // Этот assert не сработает
    return 0;
}
```

1. **Безопасность: можно ли полагаться на `assert` в рабочем коде?**
    
    - Нельзя использовать `assert` для обработки ошибок, так как он удаляется в релизной сборке.
    - Например, если входные данные приходят извне (например, от пользователя), использовать `assert` — ошибка.
2. **Как `assert` влияет на производительность?**
    
    - В отладочной сборке `assert` проверяет выражения, что может замедлять код.
    - В релизе (`NDEBUG`) `assert` не компилируется, влияния на производительность нет.

---

### 📌 **Сравнение с другими подходами**

|Подход|Как работает|Преимущества|Недостатки|
|---|---|---|---|
|**assert**|Аварийное завершение при ошибке|Простота, отладка|Отключается в релизе|
|**if + exit()**|Проверяет и вызывает `exit()`|Работает в релизе|Не сообщает строку и файл|
|**if + abort()**|Проверяет и вызывает `abort()`|Аналог `assert`, но не отключается|Аварийное завершение|
|**if + return/error**|Возвращает код ошибки|Гибкость, явная обработка|Нужно обрабатывать ошибки вручную|

#### 📌 **Пример разницы между `assert` и `if + exit()`**

```c
#include <assert.h>
#include <stdlib.h>
#include <stdio.h>

void check_assert(int x) {
    assert(x > 0);
    printf("x is valid\n");
}

void check_exit(int x) {
    if (x <= 0) {
        fprintf(stderr, "Error: x must be positive\n");
        exit(1);
    }
    printf("x is valid\n");
}

int main() {
    check_assert(-1); // Завершит программу только в отладке
    check_exit(-1);   // Завершит программу всегда
}
```

🔹 `assert` можно выключить в `NDEBUG`, а `if + exit()` всегда работает.

### 📌 **Вывод**

🔹 `assert` — мощный инструмент для отладки, но его нельзя использовать для обработки ошибок в рабочем коде.  
🔹 Его легко отключить с `#define NDEBUG`, но это делает код уязвимым, если `assert` использовался для реальных проверок.  
🔹 В релизной версии лучше использовать `if + exit()`, `if + return`, `perror()`, `strerror()` или обработку исключений (если поддерживается).
