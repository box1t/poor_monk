In the given struct `MappedFile`, the member `data` is declared as a pointer to a character, `char *`. This is a common practice in C programming, especially when dealing with dynamically allocated memory.

2. **Flexibility**: Using a pointer allows for flexibility in the size of the data. You can allocate memory based on runtime conditions or user input.

3. **Efficiency**: Storing data directly inside a struct (like an array) can lead to wasted memory if the data size varies or if the struct is frequently passed around. Using a pointer avoids this overhead since only the memory address is stored in the struct, not the actual data.

4. **Data Representation**: While `char *data` is a pointer to a character, it can indeed represent a string or an array of characters in C. Strings in C are represented as arrays of characters terminated by a null character (`'\0'`). So, `char *data` can be used to point to such strings or character arrays.

5. **File Mapping**: Considering the name of the struct (`MappedFile`), `char *data` could potentially point to the memory-mapped contents of a file. Memory mapping is a technique in operating systems that maps a file into memory so that it can be directly accessed.

The communication between the server and client in this code is managed using a shared memory region (`MappedFile`) and mutexes for synchronization. Here's how it works:

1. **Shared Memory Region (`MappedFile`)**: The `MappedFile` struct likely represents a shared memory region between the client and the server. This shared memory region is used to exchange messages between them. The client writes messages to this memory region, and the server reads them (and vice versa).

2. **Mutex (`pthread_mutex_t`)**: The mutex (`pthread_mutex_t mutex`) is used to ensure that only one thread (either client or server) accesses the shared memory region at a time. This prevents race conditions and ensures data integrity during communication.

3. **sendMessageToServer()**: When the client wants to send a message to the server, it locks the mutex using `pthread_mutex_lock()` to gain exclusive access to the shared memory region. Then, it clears the memory in the mapped file (`memset(mappedFile.data, '\0', _MAPPED_SIZE)`) and copies the message into the mapped file using `sprintf()`.

4. **getAnswerFromServer()**: This function is responsible for retrieving and processing responses from the server. It first checks if there's a message available in the shared memory region. If so, it reads the message, parses it, and performs actions based on its content.

5. **Mutex Unlocking**: After sending or receiving messages, the client unlocks the mutex using `pthread_mutex_unlock()` to allow other threads (potentially the server) to access the shared memory region.

1. **String Message (`std::string message`)**:

   - This string is typically used when receiving a message from the server or preparing a message to send to the server.

2. **Vector of Commands (`std::vector<std::string> serverCommands`)**:
   - Represents the parsed components of a message as individual strings stored within a vector.
   - Each element of the vector corresponds to a separate command or piece of information extracted from the message.
   - This vector is populated by parsing the original message string.

    int direction; // Direction of wall extension (0 for vertical, 1 for horizontal)
    int axis[2]; // Coordinates of the current position
    int y; // Flag to indicate if the current position is valid
    srand(time(0)); // Seed the random number generator with current time
    
    // Iterate over each wall segment
    for (int wallLength = 4; wallLength > 0; wallLength--) {
        for (int k = 5; k - wallLength; k--) {
            // Randomly determine the direction of the wall extension
            direction = 1 & rand();
            do {
                // Generate random coordinates for the current position
                axis[direction] = 1 + rand() % 10;
                axis[1 - direction] = 1 + rand() % 7;
                
                // Check if the position is valid (not overlapping with existing walls)
                for (y = 0; y - wallLength; y++) {
                    if (map[axis[0]][axis[1]] != '.') {
                        // Position is not valid, try a new one
                        axis[1 - direction]++;
                        y++;
                    }
                }
