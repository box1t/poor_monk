# Concept

Концепт представляет собой именованный набор ограничений на один или
несколько параметров шаблона.

```c++
Вот как выглядит наш привычный шаблон max () с двумя параметрами при
использовании ограничения

template <typename T> requires LessThanComparable<T>
T max (T a, T b)
{
	return b < a ? a : b;
}

Такой концепт представляет собой булев предикат (т.е. выражение, которое
производит значение тина bool), вычисляющий константное выражение. 

Ограничения проверяются во время компиляции и 
не создают никаких накладных расходов.


Можно также выразить “альтернативные” требования с помощью | |. Это ред­
ко необходимо, и обращаться к этому способу следует с осторожностью, так как
чрезмерное использование оператора | | в конструкциях требований может по­
тенциально потреблять ресурсы компилятора (и заметно замедлять компиля­
цию). Однако в некоторых ситуациях это может быть очень удобно. Например:


template<typename Т>
requires Integral<T> || FloatingPoint<T>
Т power(Т b, Т р);


Одно требование может включать несколько параметров шаблона, и один концепт
может выразить предикат над несколькими параметрами шаблона.

template<typename Т, typename U>
requires SomeConcept<T, U>
auto f(T x, U y) -> decltype(x + y)

Таким образом, концепт может устанавливать связь между параметрами типов.
```



# Variadic template

Это дает возможность использовать шаблоны
в местах, где требуется передать произвольное количество аргументов произ­
вольных типов. Типичное приложение этой возможности — передача произволь­
ного количества параметров различных типов в класс. Еще одно применение —
предоставить обобщенный код для обработки любого количества параметров
произвольных типов.

Например, можно использовать приведенный ниже код для вызова функции
print () для переменного количества аргументов разных типов:
```c++
#include <iostream>
void print(){}

template <typename T, typename... Types>
void print(T firstArg, Types... args) {
	std::cout << firstArg << "\n"; // печать первого аргумента
	print(args...); // вызов print() для остальных аргументов
}

// print() применяется рекурсивно для остальных элементов
```

Остальные аргументы, представленные именем args, являются
пакетом параметров функции (function parameter pack)



Когда для вариативного шаблона определяются аргументы шаблона, каждый
пакет параметров шаблона соответствует последовательности из нуля или боль­
шего количества аргументов.

Аргумент шаблона Types . . . представляет собой раскрытие пакета, которое
создает последовательность аргументов шаблона, по одному для каждого аргу­
мента в пакете аргументов, подставляемом вместо Types. Как показано в этом
примере, инстанцирование типа MyTuple<int, f loat> подставляет пакет ар­
гументов int, float вместо пакета параметров типов шаблона Types. Когда
это происходит при раскрытии пакета Types. . мы получаем один аргумент
шаблона для int и один для float, так что MyTuplecint, float> наследует
Tuplecint,float>.

Каждое раскрытие пакета имеет свою схему (pattern), которая представляет
собой тип или выражение, которое будет повторяться для каждого аргумента

в пакете аргументов, и обычно располагается перед многоточием, обозначающим
раскрытие пакета


variadic templates && fold expressions - шаблоны переменного числа аргументов, необходимый механизм для функций `make_unique`, `make_shared`, `emplace_back`.

# Хвостовая рекурсия на стадии компиляции

Хвостовая рекурсия - это особый тип рекурсии, при котором вызов рекурсивной функции происходит в самом конце тела функции, после ее вычислительной работы. Такой подход позволяет компилятору или интерпретатору оптимизировать код и не сохранять значения всех промежуточных вызовов в стеке вызовов, что может привести к проблемам с памятью. Вместо этого, компилятор или интерпретатор могут заменить несколько последовательных вызовов рекурсивной функции на один вызов, используя только один фрейм стека вызовов. Это снижает использование памяти и повышает производительность


```c++
##### just for fun: compile-time факториал

template<unsigned N>
struct Factorial
{
    static const int value = N * Factorial<N - 1>::value;
};

template<>
struct Factorial<0>
{
    static const int value = 1;
};

int main()
{
    return Factorial<10>::value;
}
```


**Вопросы**:

- Что делает следующий пример?


```c++
#include <cstdio>

template<unsigned N>
struct f
{
    static const int value = f<N-1>::value + f<N-2>::value;
};

template<>
struct f<0>
{
    static const int value = 0;
};

template<>
struct f<1>
{
    static const int value = 1;
};

int main()
{
    printf("%i\n", f<45>::value);
}
```


```
Этот пример реализует вычисление чисел Фибоначчи во время компиляции с использованием шаблонов и статических переменных. 

Основные моменты:

1. В шаблонной структуре `f`, мы определяем переменную `value`, которая содержит значение числа Фибоначчи для заданного `N`. 

2. Первые два числа Фибоначчи (0 и 1) определены как специализации шаблонов `f<0>` и `f<1>`.

3. Для всех других значений `N`, `f<N>` рассчитывается как сумма предыдущих двух чисел Фибоначчи, которые вычисляются рекурсивно.

4. В функции `main()` выводится значение числа Фибоначчи для `N = 45`, используя `printf`.

Однако, следует отметить, что для `N > 45` это может потребовать значительного времени компиляции из-за экспоненциального роста вычислений в процессе компиляции.
```
