### Альтернативы push_back


Альтернативы `push_back` зависят от контекста использования и требований к вашему коду. Вот несколько основных альтернатив:

#### 1. Обращение по индексу
Если вы знаете размер вектора заранее, вы можете инициализировать вектор с нужным размером и использовать обращение по индексу:
```cpp
std::vector<int> result_vec(size); // Инициализация вектора с известным размером
result_vec[i] = value; // Прямое присвоение по индексу
```
Это позволяет избежать дополнительных затрат на перераспределение памяти, связанных с `push_back`.

#### 2. Использование метода `emplace_back`
Если вы хотите добавить элемент в конец вектора и при этом избежать лишнего копирования, вы можете использовать `emplace_back`, который создает элемент на месте:
```cpp
result_vec.emplace_back(value);
```
Это может быть полезно, если вы работаете с объектами, так как `emplace_back` может избежать создания временных объектов.

#### 3. Использование метода `insert`
Если вам нужно вставить элемент в определенную позицию в векторе, вы можете использовать метод `insert`:
```cpp
result_vec.insert(result_vec.begin() + index, value);
```
Этот метод позволяет вставить элемент в любое место в векторе, но может быть менее эффективным, чем `push_back`, так как требует сдвига элементов.

#### 4. Инициализация вектора с помощью списка инициализации
Если вы заранее знаете все значения, которые хотите добавить в вектор, вы можете инициализировать его с помощью списка инициализации:
```cpp
std::vector<int> result_vec = {value1, value2, value3};
```
Это позволяет сразу задать значения вектора без необходимости использовать `push_back`.

#### 5. Использование `reserve` для предварительного выделения памяти
Если вы знаете, сколько элементов вы собираетесь добавить, вы можете использовать метод `reserve`, чтобы заранее выделить память для вектора:
```cpp
result_vec.reserve(size); // Предварительное выделение памяти
```
Затем вы можете использовать `push_back` без риска перераспределения памяти, если количество добавляемых элементов не превышает выделенный размер.

#### Заключение
Альтернативы `push_back` могут быть полезны в зависимости от ваших требований к производительности и структуре данных. Выбор подходящего метода зависит от контекста использования, размера данных и необходимости в управлении памятью.

### Индексированный доступ (почему не индексируемый?)
- верно ли понимаю, что индексированный доступ к вектору (включая добавление по индексу) предполагает, что заранее известны его границы, поскольку реаллокации не будет, в отличие от push_back?

- **`push_back`:**
  - Удобно, когда вы не знаете заранее, сколько элементов будет в векторе.
  - Позволяет динамически изменять размер вектора.
  - Может быть менее эффективным, если вектор часто изменяет размер, так как может потребоваться перераспределение памяти.

- **Обращение по индексу:**
  - Более эффективно, если вы знаете, сколько элементов будет в векторе заранее, и можете инициализировать его с нужным размером.
  - Позволяет избежать дополнительных затрат на перераспределение памяти.
  - Требует, чтобы вектор был инициализирован с достаточным размером, иначе это приведет к ошибке выхода за пределы.
